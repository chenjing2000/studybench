# English Module V0.5 Specification

## 1. Article class families

StudyBench uses two independent base classes:

- `Article`: complete Passage, Segment audio required, Passage Audio/TTS capability present;
- `ArticleBlank`: Passage with `[[n]]` blanks, Segment `audio` forbidden, no Passage Audio/TTS methods.

Extended classes:

- `ArticleChoice(Article)` → `article_choice`
- `ArticleAnswer(Article)` → `article_answer`
- `ArticleCloze(ArticleBlank)` → `article_cloze`
- `ArticleClozeWords(ArticleBlank)` → `article_cloze_words`
- `ArticleClozeSentences(ArticleBlank)` → `article_cloze_sentences`

`Article` and `ArticleBlank` do not inherit from one another.

## 2. Passage schema

All Passages keep `title`, `next_sid`, ordered `paragraphs`, and lowercase `s001`-style SIDs.

`Article` Segment:

```json
{
  "sid": "s001",
  "text": "A complete sentence.",
  "audio": {
    "uk": "audio/s001_uk.mp3",
    "us": "audio/s001_us.mp3"
  }
}
```

`ArticleBlank` Segment:

```json
{
  "sid": "s001",
  "text": "A [[1]] sentence."
}
```

`Article` forbids any `[[n]]` marker. `ArticleBlank` forbids `audio`, requires at least one valid `[[n]]`, and each placeholder number appears exactly once.

## 3. Exercise schema

`exercise.json` is optional and stores textbook exercise data only.

### article_choice

Top-level `type`, then `questions[]` with:

- `number`
- `prompt`
- `options[]` (`key`, `text`)
- `reference_answer`
- `explanation`

Choice prompts cannot contain `[[n]]`.

### article_answer

`questions[]` contains `number`, `prompt`, `reference_answer`, `explanation`.

### article_cloze

`items[]` contains `number`, per-item `options[]`, `reference_answer`, `explanation`.

### article_cloze_words

`items[]` contains `number`, required string `cue` (empty string allowed), `reference_answer`, `explanation`.

### article_cloze_sentences

Top-level shared `options[]`; `items[]` contains `number`, `reference_answer`, `explanation`. Shared option keys are single uppercase characters.

For all three blank exercise types, `items[].number` must match Passage `[[n]]` exactly.

## 4. Factory and fallback

`article_classes/factory.py` is the only type dispatch location.

- supported type → matching class, strict validation;
- no exercise → `Article` if no placeholders, otherwise `ArticleBlank`;
- unsupported type → same fallback rule plus warning;
- corrupt JSON or invalid supported schema → error, no fallback.

## 5. Page payload

Python sends one page payload:

```json
{
  "article_family": "article",
  "passage": {"title": "...", "paragraphs": []},
  "exercise": null,
  "answers": null,
  "warning": null
}
```

`article_family` is a runtime payload field and is not stored in `passage.json`.

## 6. Rendering

`passage.js` renders only two Passage families. `exercise.js` independently renders five exercise types. Extended classes do not alter Passage DOM.

`ArticleBlank` converts each `[[n]]` to a non-audio numbered blank. Vocabulary selection/highlighting remains available.

## 7. User answers

Per-account `answer_sheet.json` stores:

```json
{
  "username": "Default User",
  "answers": {
    "passage_folder": {
      "type": "article_choice",
      "answers": [
        {"number": 1, "answer": "A"}
      ]
    }
  }
}
```

No `user_answer`, `user_note`, copied reference answer, or stored correctness flag is used.

The UI autosaves dirty answers after a short debounce and flushes before leaving the current answer context.

## 8. Vocabulary

Vocabulary is independent of the Article hierarchy and works for both base families. Vocabulary audio stays under `audio_vocabulary/` and is generated by the separate `gen words audio` pipeline.
